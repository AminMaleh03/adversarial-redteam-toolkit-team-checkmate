METHOD & LIMITS

Read this demo in context.

Four defenses, one shared model

  1. Length validation. Reject sequences over the model's limit before inference.
  2. Strict request types. Reject wrong types and unexpected fields.
  3. Scoped exception handling. Contain unexpected errors while preserving validation responses.
  4. Unicode and whitespace cleanup. Normalize text before inference.

V1 and V2 run the identical model; only V2 adds these four application-layer defenses. No retraining, no silent truncation.

What this demo does and does not show

  • This demo mode runs a curated subset of the full attack suite so it finishes quickly for a live audience -- the same runner, same attack definitions, same real inference and analysis as full mode, just fewer cases.
  • V2's defenses are application-layer only; a persisting prediction-flip weakness on V2 is an honest non-improvement, not a gap in the hardening -- fixing it needs model-level work, not endpoint code.
  • A failed post-request health check is observed unavailability only. It is not proof that the underlying operating-system process terminated.
  • The complete technical evidence -- full finding register, audit appendix, and case-level detail -- exists in the Technical Report{% if detailed_report and detailed_report.available %} (view it here){% endif %}, not in this demo page.
